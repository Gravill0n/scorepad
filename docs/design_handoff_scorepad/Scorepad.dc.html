The one I'd ship
49 cells become seven screens of seven rows: no horizontal scroll, no truncation, 72px rows, 48px cells. Three things it buys that the others don't — the category name and its rule get the full 390px (the French label wraps instead of clipping), the table hears one question at a time ("military?") which is how end-of-game scoring is actually called out loud, and every number sits beside its six peers, so an outlier is visible the instant it's typed. That peer check is the real error correction; a lone column has none.

Tally mode — from two teams to twelve players

Standings are the screen. The ledger gets its own.

A per-hand ledger laid across the screen — one column per player, one row per hand — only works while every player fits inside 390px: two teams, three at a squeeze. Black Lady seats seven, Uno ten. Widening that grid means horizontal scroll on the one screen the table stares at all evening, and the running totals, the only numbers anyone ever asks for, are the first thing scrolled off.

So the primacy flips. Standings become the screen: one row per player, stacked vertically, scaling from 2 to 12 by getting denser rather than wider. The per-hand ledger keeps every number but moves to its own screen (2d) — it is audit material, opened to settle a dispute, not read continuously. And a hand is no longer two boxes: it is one sheet that walks the table (2c), the same gesture whether the table is two people or ten.

One row per player, so the table size changes the density and never the layout
Vertical rows are the only axis a phone has to spare, and a row can carry more than a grid cell could: rank, colour, name, hands won, what the last hand added, the total at 38px, the distance to the target, and a bar showing the race. That is the whole state of the game read at arm's length, which is what the old ledger could never show for more than two.
Rows stay in seat order and never re-sort — rank is a number in the margin, not a position, so the person you are looking for is where they were last hand (the same rule the sheet mode follows; sorting happens once, on Results). The last hand is recapped as one mono line naming who scored, with the correction affordance beside it; the per-player deltas live in the rows themselves, where three-digit scores can't overflow. Rejected: a row of per-player chips above the list — at six players with three-digit hand scores the last chip is clipped, and it duplicated what every row already says.

One sheet walks the table: N numbers, N taps of the same key
The old design gave each team its own box because two boxes fit. Ten don't. Instead the sheet keeps one keypad and moves the cursor: type, press the name of the next player, repeat; the last press saves the hand and closes the sheet. The chip row above the keypad is both progress bar and random access — tap any chip to jump back when someone corrects themselves two players later, which is the failure the strictly-sequential flow could not survive at this table size.
Chips are player-sized, not fixed: at ten they lose the initial circle and keep the number. Black Lady is drawn here because it is the hard case — every player scores every hand, low wins, and the hand must total 26, so the header carries a live 26 à répartir · 7 placés check and refuses a save that doesn't balance. Games without a fixed hand total simply don't show that line. Rejected: a modal per player (five dialogs a hand), and a spreadsheet-style row of five inputs with the system keyboard (each field ~62px wide, numbers unreadable, and the keyboard hides half of them).

The rework had to not regress the case it was built for. Colour is never the only difference
Twelve hues cannot all be told apart under deuteranopia — anyone claiming otherwise is selling you a palette. So every token carries the player's initial at 15px/600, and rows are labelled with the full name; the colour is a fast index, not the identity. Assignment order is fixed and front-loaded for separability: blue, orange, teal, magenta, green, red covers the common six-player table with pairwise-distinct hues under all three dichromacies. Colours 7–12 are only reached at a ten-player Uno, where the name is doing the work anyway.
One lightness per theme, one chroma for all
Fixed L and C mean no hue shouts louder than another, and every token clears 4.5:1 with its letter. Values are re-derived per theme rather than reused: L 0.53 on paper, L 0.72 on dimmed paper. Taken colours dim to 32% in the picker instead of disappearing, so the grid never reflows under a thumb. The accent #a8431d and alarm #b3261e are deliberately excluded from the player palette — a player must never be mistaken for a state.
